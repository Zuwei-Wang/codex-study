# 小范围试用指南

[English](PILOT.md)

由项目负责人安排 2–3 位试用者，目前尚无真实安装或试用反馈。先只用仓库原创虚构资料。反馈使用代号，不写学号、邮箱或真实课程内容；不要把学校页面截图、浏览器状态、令牌或私人笔记发到公开 Issue。

## 试用版本与准备

第一轮固定使用 **386d8babc6d55119aaac4bb998eb1a303cc348de**（M3、0.3.0 开发预览版）。该提交的 [Ubuntu 与 macOS GitHub CI](https://github.com/Zuwei-Wang/codex-study/actions/runs/37852125088) 均已通过。M4 仍在开发验收，不影响先试用本地学习功能。若改用其他版本，请记录完整 SHA，并单独核对对应 CI。

需要 macOS/Linux、Node 24.21.0、npm 11.12.1，以及支持本地插件的 Codex。已自动验收的 Codex CLI 是 0.144.4。虚构课程演示不需要学校账号或邮件服务；AI 对话使用试用者自己的正常 Codex 账号。Windows 暂未验收。

```sh
git clone https://github.com/Zuwei-Wang/codex-study.git
cd codex-study
git checkout 386d8babc6d55119aaac4bb998eb1a303cc348de
# 先通过自己的版本管理器选择 Node 24.21.0。
npm install --global npm@11.12.1
npm ci --ignore-scripts
npm run demo -- "$HOME/codex-study-pilot"
npm run plugin:build -- build/pilot-v0.3.0
npx --no-install codex plugin marketplace add "$PWD/build/pilot-v0.3.0"
npx --no-install codex plugin add codex-study@codex-study-local --json
```

插件安装命令会修改你正常使用的 Codex 配置。安装后重启 Codex 或新建会话，并确保它能找到 Node 24。遇到已有插件注册冲突时，按[安装说明](INSTALLATION.md)排查，保留原配置。学习目录应放在仓库和插件目录之外，不要用重新初始化覆盖已有学习数据。

## 试用任务（约 30–45 分钟）

1. 连续运行两次虚构演示。确认两个资料版本、冲突日期、明确记录的 `read` 进度、带引用笔记和 `doctor.ok: true`；重复运行不应产生重复记录。
2. 请 Codex 读取虚构课件第 2 节，讲解并出一道自测题，保存带引用笔记。打开笔记，对照原文核对引用位置和内容，并评价解释是否有助理解。
3. 明确要求把一项虚构任务标为 `drafted`，再导入原资料。确认进度保留，没有自动变成已提交或已评分；单纯打开或读取也不应自动记录完成。
4. 用私人输入文件导入仓库虚构 ICS，将 `file` 指向实际课表文件。检查三次课程、伦敦夏令时切换和明确的课程映射。示例固定为 2030 年，不是你的真实课表。
5. 在没有授权学校浏览器连接的情况下请求一次限定范围检查。系统应如实记录能力不可用，不能把空结果当成检查成功。真实平台检查可选，必须使用本人授权会话，真实资料保留在私人目录。
6. 查看每周复盘、日期冲突和未知信息的呈现，记录会误导学习进度或混淆“已发布资料/课堂实际内容”的地方。

安装成功、配置成功和合成邮件演示，都不代表无人值守检查或真实提醒投递成功。每日调度、真实学校检查和提醒服务各自需要单独验收，不必为了完成首轮试用而启用。

## 反馈

填写[反馈模板](pilot-feedback-template.md)：版本、环境、实际尝试的任务、结果、匿名错误信息与复现步骤。“未尝试”“受阻”“失败”应分别记录。可随时停止试用。由负责人私下收集；只有经过脱敏并取得试用者同意的摘要才进入公开仓库。

M5 的通过条件是至少另一位真实用户成功安装所选版本、运行文档演示，并能区分已实现、实验性与计划中功能。2–3 人是计划规模，目前不是已完成结果。AI 教学质量需试用者实际评价，引用校验通过不能代替这一点。
